# Project Constitution

| Field | Value |
|---|---|
| Status | Approved (2026-10-03) |
| Applies to | Every spec, tech file, task and line of code in this repository |
| Last updated | 2026-10-03 |

These principles are **non-negotiable**. A spec or tech file that conflicts with one of them is wrong
and must be changed, unless the constitution itself is amended first (see "Amending" at the end).

---

## P1 — Free first
The product must run at **$0/month** for its first phase.
- Every hosted service must be used within its free tier.
- Every tech file lists the free-tier limits it relies on, with a source link and the date it was verified.
- Any paid dependency (even $1) needs explicit owner approval **and** a spec change before it is used.
- When a free tier is about to run out, the product degrades gracefully (fewer or slower results);
  it never starts spending money silently.

## P2 — Spec before code
- No code is written for a feature until its `spec.md` (what and why) **and** `tech.md` (how) are approved.
- Changes flow in one direction: **spec → tech → tasks → code**. If code needs to differ from the spec,
  the spec is updated first.
- `spec.md` files stay technology-agnostic. Technology names belong only in `tech.md`.

## P3 — Honest availability and honest prices
- A domain is only labelled **available** if we checked it within its freshness window (TTL).
- Every result shows **when** it was checked and **where** its price came from.
- If we are not sure, we say so ("likely available, confirm at registrar") instead of guessing.
- We never invent prices. A domain with no sourced price is shown without a price, not with an estimate.

## P4 — Jev judges, it never authors
- Jev (TypeSafe's decision model) is used to **decide, classify, score and rank**.
- Domain name candidates are generated by our own deterministic code.
- The product must still work, in a degraded mode, when Jev is unavailable or its budget is used up.
- Jev's model version is pinned in production and upgraded only after an evaluation run.

## P5 — Privacy by default
- Searching never requires an account.
- Raw website descriptions from anonymous users are never stored.
- We collect the minimum data needed, keep it for the shortest useful time, and never sell or share it
  for advertising.
- No tracking cookies. Only strictly-necessary cookies (e.g. sign-in session) are allowed.
- Users can export and delete their data at any time.

## P6 — Safety over coverage
- We never recommend names that imitate well-known brands (lookalikes, typos, brand + "login", etc.).
- We refuse to generate names for descriptions showing phishing, impersonation, fraud or clearly illegal intent.
- When in doubt, a name is excluded rather than shown.

## P7 — We recommend, registrars sell
- The product does not register domains, take payments or hold user money.
- "Buy" buttons send users to a registrar.
- No affiliate or paid links while the site runs on a non-commercial free hosting plan.

## P8 — Every metered call has a cap
- Every external call that can cost money or hit a rate limit (Jev, RDAP, DNS, e-mail, word APIs)
  has a per-request, per-day and per-month cap, enforced in code.
- Caps are configuration, not constants buried in code.

## P9 — Accessible and fast
- The interface meets **WCAG 2.2 level AA** and works on a mid-range phone.
- First useful results appear in under 5 seconds for a typical search.

## P10 — Traceability
- Every functional requirement (`FR-…`) and non-functional requirement (`NFR-…`) appears in the
  traceability matrix of its `tech.md`, mapped to a component and at least one test.
- A requirement without a test is not done.

---

## Amending the constitution
1. Open a change describing which principle changes and why.
2. List every spec and tech file affected.
3. The owner approves the change.
4. Update this file first, then the affected specs, then the tech files.
